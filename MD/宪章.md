XuePilot 派乐伴学 - 系统架构与生态宪章 (V13.0 Ultimate)

核心定位: 专为家庭与创新教育者打造的下一代 AI 伴学系统 (Homeschooling OS)。
核心哲学: “AI 时代，人不再是干活的工具，而是思想的源头。我们要教孩子如何提问、判断、整合，体验驾驭算力的快感。”

一、 双端物理隔离架构 (Dual-Domain Architecture)

XuePilot 严格将“学习探索权”与“教研管理权”在物理（文件）层面切分，维护极致的产品沉浸感。

1. The Explorer Deck (学生前台探索舱 - classroom.html)

定位：纯粹的 3A 级沉浸式 3D 学习与认知扩展空间。

净化原则：绝对禁止在此界面出现“生成大纲”、“编辑参数”、“配置数据库”等生硬的后端功能。

核心模块：

3D 知识星球 (Galaxy)：动态渲染引力网格与曲率粒子，展示家长部署的学习任务。

全球教育智库 (Edu-Vault)：通过 Supabase 实时抓取真实的不规则 K-12 教学大纲与开源教材。支持极客级 3D 翻牌特效。此处仅限“阅览”和“一键申请建星”，建星请求发送至家长后台。

苏格拉底写作舱/伴读舱 (Socratic Labs)：以“提问”、“逻辑找茬”为核心。

2. The Command Center (家控教研中枢 - dashboard.html)

定位：数据驱动、操作高效的家长/教师控制台。

门禁系统：由 Parent PIN (默认 0000) 守护，有效阻挡学生误入。

核心模块：

星系锻造中枢 (The Forge)：通过三步走 RAG 协议（大纲投喂 -> 课标对齐 -> 科幻重构），将现实教学计划转化为科幻知识星球。

全息学情雷达 (Insight Radar)：通过苏格拉底互动数据，生成多维认知评估图谱。

全局系统配置：统一收口 API Key 填写与算力引擎指定。数据库 (Supabase) 凭证通过底层硬编码，对前端 UI 屏蔽以保整洁。

二、 全球智库与数据爬虫生态 (Global Edu-Vault & Spider)

系统不再依赖低级的、规则整齐的硬编码 for 循环生成假大纲。

极致真实的异构数据：数据库中的教学大纲必须反映真实世界的参差不齐（例如有的学期 15 个模块，有的只有 4 个模块）。每一个模块都必须具备 hours (课时)、objectives (达成要求)、key points (核心知识点)。

树状无限层级 (Hierarchical UI)：前台智库大纲采用双层级折叠面板（Subject -> Grade -> Term），只在最底层的具体学期才展示 【✨ 申请以此排课建星】 按钮。

教材沉浸式阅读器：对于抓取入库的开源教参（如 OpenStax），前端不跳转外链，而是通过内置的全息双栏阅读器（左目录、右图文）原生渲染。

外部爬虫脚本 (xuepilot_spider.py)：通过 Python 爬虫结合 BeautifulSoup，向 Supabase 实时投喂真实的外网教研资产。

三、 苏格拉底引擎法则 (Socratic Engine Rules)

XuePilot 的所有大模型 Prompt 指令必须严格遵循以下接生术金律：

不代写、不直给答案。

多反问、找漏洞：“作为侦探，分 3 点指出他逻辑上的断裂，并用问题引导他修复。”

锯齿形能力辅助：AI 负责逻辑排版与数据提供，逼迫孩子提供创意、审美和情感维度。

四、 商业变现拦截网 (Aha Moment Paywalls)

系统不采用传统的“时间试用限制”，而是通过“能力阈值”和“科幻包装”勾起用户的付费欲。

量子算力锁 (API Lock Paywall)：免费用户在写作舱、伴读舱等重度交互功能中，若未绑定 API，不报错，而是抛出温和且极客的拦截窗：“算力未接入，目前为演示模式。请连接指挥中心的真实 AI 引擎。”

智库深度锁 (Vault Depth Paywall)：在浏览全球教育智库时，仅开放少数几个（如中美体系）供免费预览。新加坡 MOE、英国 KS2、外网开源教材等优质资产均打上 PRO 锁，点击即提示 “该档案需要极高的量子算力去外网解密，请升级 PRO。”

五、 前端技术极客规范 (Geek-Level Dev Rules)

栈选型：HTML 单文件架构、TailwindCSS (视觉)、Alpine.js (状态驱动)、SweetAlert2 (科幻弹窗)、Quill.js (含图文富文本)。

原生 3D 渲染：星系网格（network-canvas）绝不使用重型框架，严格使用纯原生 Canvas 2D API（ctx.arc, ctx.lineTo）构建高性能的引力连线与星点矩阵。

绝对不要阉割功能：在进行任何 UI 修改或代码重构时，绝不能为了“代码体积”而牺牲原有的资源数量（如 12 个探索网站必须全部保留）或抹除现有的动态视觉效果。
